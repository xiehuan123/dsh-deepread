# dsh-deepread 1.0.0-rc.1

This prerelease was published under the npm `next` dist-tag as the installation candidate for `1.0.0`.

This release candidate moves the public Host implementation and browser source to strict TypeScript while keeping the `deepread` tool schema and the `0.5.4` persistence formats compatible.

## Compatibility

- Node.js now requires `^22.19 || >=24`.
- DeepSeek Harness Web `0.1.0-rc.7` loads the Host tool, packaged skill, budget route, result card, and reading panel.
- DeepSeek Harness headless `0.1.0-rc.7` loads the Host tool and skill without requiring Web services; it does not load the browser client or register the budget route.
- dsh-TUI `0.8.1` or newer loads the Host tool and packaged skill through the Community Consensus v0.15 manifest. It does not load the DeepSeek Harness Web client.
- A composition without `storageDomain` keeps working with process-local URL cache and Host calibration.

## Package and entry changes

- The npm package remains `dsh-deepread`; the Cordis plugin and tool remain `deepread`.
- The package root now imports `lib/types/index.js` and publishes declarations from `lib/types/index.d.ts`.
- `dsh-plugin.json` is a Host-only v0.15 manifest. It intentionally has no client or worker facet.
- `lib/client.js` remains an optional DeepSeek Harness Web entry exposed as `dsh-deepread/client`; it is not a dsh-TUI client facet.
- Handwritten runtime sources are TypeScript. `lib/types/**/*.js`, declarations, and `lib/client.js` are generated build artifacts.

## User-visible improvements

- The reading button now opens and closes one panel instance; the close button uses the same state.
- The panel supports pointer dragging with viewport constraints and resize correction.
- The Web UI follows Harness semantic theme tokens in light and dark modes.

## Upgrade and data

There is **no data migration** for this release. The Web history and budget-calibration localStorage keys, URL cache domain v1, and Host calibration domain v1 are unchanged and remain readable in both directions with `0.5.4`.

Data remains visible when the browser origin and `DSH_HOME` stay the same. Changing either selects a different namespace or storage directory; clearing browser site data deletes localStorage independently of the plugin upgrade. See the [upgrade and rollback guide](../upgrade-and-rollback.md) for exact conditions and rollback commands.

## Status

This candidate is retained as a prerelease. Install the stable `1.0.0` release for normal use.
